## 2. 产品主线

首个可用版本 M1：**规格 → 候选谐振腔 → 多工况检查 → 方案比较 → 设计版本 → 计算书**。

数学与信号处理模块经独立验证后复用；产品流程、数据模型和业务编排按 V2 契约重建。现有 V1 API、数据库、报告和运行方式在 T01 保持不变。

M1 范围：半桥 LLC、变频、硅 MOSFET、固定单输出、中心抽头二极管整流；n = Np / Ns_half。产品定位延续 300–1000 W、300–420 VDC、24 V / 48 V。副边连接明确化只约束新 V2 模型，不能自动重解释 V1 项目。

M1 计算限定理想稳态 FHA 与正负载。空载、启动、突发、短路、瞬态、实际效率、磁件可制造性和完整 ZVS 尚需后续能力；不得把未实现项写成已通过。来源不明的器件值、搜索范围或工程裕量不得静默补充。

## 6. 下一项任务：T02

目标：建立可供后续分析绑定的 Project、RequirementSet、DesignRevision 草稿与冻结基础。

### 6.1 实施范围

- 按 V2 命名空间增加领域对象和持久化映射；V1 数据表和接口保持兼容。
- RequirementSet 与 DesignRevision 保存来源、父版本、状态、时间和版本标识。
- Draft 可编辑，Frozen 不可覆盖；从冻结版本修改需派生新的 draft。
- 草稿编辑使用版本号或 ETag 检测并发修改，重复冻结具有明确的幂等行为。
- 冻结设计必须绑定明确且已冻结的需求版本；跨项目引用被拒绝。
- 冻结过程原子化，失败不能留下“已冻结但内容未完成”的中间状态。
- 此任务先提供领域/应用接口及必要测试；完整业务 HTTP API 属于 T07，前端属于 T08。
- T02 的不可变版本标识与并发控制先落地；T03 定义规范化内容哈希，不能在 T02 用临时哈希冒充最终运行指纹。

### 6.2 验收与停止点

测试创建、编辑、派生、冻结、重复冻结、冻结后拒绝修改、并发冲突、跨项目引用、事务回滚与 V1 兼容。数据库变更通过可追溯 migration；在隔离测试数据库验证，不在用户原数据库自动迁移。

完成 T02 的实现、相关测试和文档后停止，不顺带实现 CaseSet、SearchProfile、候选综合或 AI 功能。若实际执行发现契约缺口，记录并修正当前范围内的设计，不默默扩展任务。

## 7. 质量与报告

- 工程模块变化运行相关测试；功能里程碑交付前运行完整后端测试。
- 前端实现变化至少运行 build；文档任务检查结构、链接和工程陈述，不伪造运行测试记录。
- 新增公式、阈值、来源解释、近似或状态必须同步对应文档。
- 软件任务成功、模型初筛通过与实测验证成功分别报告。
- 完成报告包含 Changes、Files、Tests、Verification、Engineering Assumptions、Limitations 和一个 Next Step。
- 提交、推送与 PR 按当前用户授权及仓库 Git 规范执行；没有自动合并或发布要求。
